# BrowserLibrary skill format, v0.1 (draft, Nov 15, 2026)

Status: draft for Rohit's review (work order BL-1). License: Apache-2.0.

## Goal
A browser skill is a folder anyone can read, install into any agent that understands SKILL.md (Claude Code, OpenClaw, SuperAssist/BrowserHand and others), and that BrowserLibrary can verify by running it. Instructions only: a skill never ships code that runs on the user's machine.

## Folder layout
```
<skill-name>/
  SKILL.md        required: what the agent reads (standard SKILL.md, so other agents can use it as is)
  browser.yaml    required: what BrowserLibrary checks and verifies (other agents can ignore it)
  check.yaml      required: how to prove the skill worked (end-state checks)
  README.md       optional: for humans browsing the library
  examples/       optional: screenshots with personal data removed
```
No other file types are accepted. In particular: no .js, .py, .sh, binaries, or archives.

## SKILL.md
Standard frontmatter, then plain-language steps.
```
---
name: godaddy-renew-domain
description: Renew a domain on GoDaddy for one year and confirm the new expiry date. Use when the owner asks to renew a domain they own at GoDaddy.
---
# Renew a domain on GoDaddy
1. Open https://dcc.godaddy.com/control/portfolio and sign in with the owner's saved GoDaddy sign-in.
2. Find {domain} in the list and open it.
3. Choose Renew, pick 1 year, and go to checkout.
4. STOP and ask the owner to approve the total before paying.
5. After payment, open the domain again and read the new expiry date.
Report: the new expiry date and the order number.
```
Rules for SKILL.md:
- Inputs are written as {name} and declared in browser.yaml.
- Any step that pays, sends, deletes, publishes or changes account settings is preceded by an explicit STOP and ask step.
- Never contain a password, API key, token, personal name, email, phone number or client data.

## browser.yaml
```
spec: browserlibrary/v0.1
name: godaddy-renew-domain        # must match SKILL.md
version: 0.1.0                    # semantic version; bump on any change
maker: github:example-maker       # verified maker account
license: Apache-2.0
summary: Renew a GoDaddy domain for one year and confirm the new expiry.
collections: [domains-and-websites]
inputs:
  - name: domain
    type: string
    example: harborandpine.example
sites:                             # every site the skill may open; nothing else is allowed
  - dcc.godaddy.com
  - www.godaddy.com
  - sso.godaddy.com
sign_in:
  - site: godaddy.com
    method: vault                  # vault only; skills never hold credentials
actions:                           # what the skill may do; anything unlisted is blocked
  read: true
  fill_forms: true
  download_files: false
  upload_files: false
  send_messages: false
  pay: ask                         # ask = only after the owner approves the exact amount
  delete: false
  change_settings: false
limits:
  max_steps: 40
  max_minutes: 10
data:
  personal_data: none              # none | reads | writes; reads/writes need a stated reason
  training_use: allowed            # allowed | never (private or sensitive skills set never)
```

## check.yaml
How the verifier proves the run worked. Checks look at the end state, not at the steps taken.
```
spec: browserlibrary/v0.1
sandbox:
  account: harbor-and-pine          # the invented test brand; never a real customer
  inputs:
    domain: harborandpine.example
end_state:
  - kind: page_text
    url_contains: dcc.godaddy.com
    expect_text_matches: "Expires\s+\w+ \d{1,2}, \d{4}"
  - kind: reported_value
    field: new_expiry_date
    expect: later_than_start
safety_expectations:
  - stopped_before_payment: true
```

## What the checker rejects (BL-4)
1. Any file type outside the layout above.
2. Secrets or personal data (pattern scan for keys, tokens, emails, phone numbers).
3. A site opened in SKILL.md that is not in browser.yaml sites.
4. A pay, send, delete, publish or settings step without a preceding STOP and ask step.
5. Sites on the do-not-automate list (sites whose terms forbid automation).
6. Missing or mismatched name, version or license.

## Badge levels
- Community: passes the checker and one sandbox run.
- Verified: 20 passing sandbox runs across 7 days, no safety flags.
- Certified: maintained by the BrowserLibrary team for BrowserHand subscribers.
